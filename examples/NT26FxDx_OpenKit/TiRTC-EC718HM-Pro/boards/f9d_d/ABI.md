# F9D_D 1.7.0 ABI 校验

HM 与另外两款产品共用 `Release_V0107`（1.7.0）。HM 使用该版本自带的 `F9D_D` 底包。[abi.mk](abi.mk) 检查构建真正使用的版本定义、启动文件、构建规则、底包 ELF、音频、网络、NVM、CSPI、JPEG 及相关 API 文件摘要。 [原厂固定提交](https://github.com/lierda-iot/CAT1.bis_OpenCPU/commit/59f1250c4b8caad4bbf4f74167b7b39c79097f8c)

| 边界 | 校验目的 |
| --- | --- |
| 3A 与停止确认 | [audio.mk](audio.mk) 根据本底包的录音缓冲池和停止回调约定配置链接入口 |
| 蜂窝网络和 MQTT | ABI 校验通过后启用本底包的网络适配 |
| 摄像头和 JPEG | 采集结束以 DMA 完成通知为准，JPEG 写入调用方提供的缓冲区 |
| 存储和分区 | 使用 `F9D_D` 原生布局。APP 物理地址 `0x2C1000`、容量 `0x2B4000`，内部文件系统物理地址 `0x575000`、容量 `0x262000` |

原厂启动表及 RAM 初始化范围保留在链接配置中。设备由已识别的 `F9D_D` 1.7.1 切换到本包 1.7.0 时，按网页提示备份并确认清除应用数据后重装。空白板、`F9D_A` 或其他无法核实的布局使用利尔达原厂初始化或恢复流程。编译检查提供 ABI 依据，屏幕、触摸、音频、摄像头和蜂窝行为以对应实板验证为准。 [构建与烧录](../../docs/构建与固件.md)
