# Pro 构建与固件

[产品首页](../README.md) · [两次烧录详细说明](../../../../firmware/pro/README.md) · [烧录步骤](当前设备操作.md#build-flash) · [主机检查](../tests/README.md)

使用完整的官方 SDK 工程与产品目录，在工程根目录运行；电脑需 Python 3.10 或更高版本。可通过 `TIRTC_PYTHON` 指定 Python 路径。现有统一入口仍生成正常应用和包含外置资源镜像的合并包：

```powershell
.\examples\NT26FxDx_OpenKit\tirtc_pro\build.bat
```

| 产物 | 用途 |
| --- | --- |
| 根目录 `firmware/pro/YYYY_MM_DD_HH_MM_SS_pro_assets.binpkg` | 官方原版工具两次烧录的第一包：完整底包与临时资源安装程序。下载后必须运行并等待 `INSTALL_OK`，由安装程序写入外置七个 UI 资源。 |
| 根目录 `firmware/pro/YYYY_MM_DD_HH_MM_SS_pro_app.binpkg` | 第二包：完整 F6D_D 底包与正式 Pro 应用，不含外置文件系统镜像；必须在资源安装成功后烧录。 |
| 根目录 `firmware/pro/YYYY_MM_DD_HH_MM_SS_pro.binpkg` | 合并包，包含 F6D_D 配套底包、应用及外置完整 UI 资源文件系统；仅适合已验证支持本板外置 Flash 写入的工具，会覆盖外置 Flash 文件。 |
| 根目录 `firmware/pro/SHA256SUMS.txt` | 当前发布包校验值。 |
| `gccout/tirtc_pro/TiRTC_pro_NT26F6D0_pro_release.binpkg` | 正式应用构建输出，是发布文件 `_pro_app.binpkg` 的来源。 |
| `gccout/tirtc_pro_assets/TiRTC_pro_Assets_NT26F6D0_pro_release.binpkg` | 独立资源安装器构建输出，是发布文件 `_pro_assets.binpkg` 的来源。 |
| `gccout/tirtc_pro_factory/` | 本地出厂镜像明细、内存映射及打包日志，不随仓库发布。 |

使用官方原版工具，推荐先全量下载 `_pro_assets.binpkg`，运行设备并等到 `[assets14] INSTALL_OK files=7 updated=... skipped=...`，再全量下载 `_pro_app.binpkg`。安装器没有正常 UI 或业务，安装结束也不会自动启动正式应用。两个包都下载到内部 Flash，第一阶段由运行中的安装程序写外置资源，因此不要求原版工具直接写外置 Flash。

升级本版时须同步安装新增的字体索引、数字字形、图标及表情参数。只有旧字形和背景的设备不能只刷正式应用包；详见 [资源说明](../resource_store/README.md)。当前配套文件名和校验方法以 [发布目录说明](../../../../firmware/pro/README.md)为准，不要混用其他资源版本的安装器。

文件名时间取对应应用或安装器 `.bin` 的真实编译完成时间（UTC+8），不是重新命名的时间。对外文件统一放在根目录 `firmware/pro/`，产品目录下不再使用 `firmware/`；镜像明细和编译中间产物保留在 `gccout`。内部 `pro_release` 名称不代表包内容相同。由旧 A 迁移时须刷写匹配的完整 D 底包与 APP，不能只刷旧设备的 APP。全量下载可能清除绑定及设置，请提前备份；正式应用包未包含外置镜像不等于所有存储均自动保留。

从源码生成两次烧录所需的包：

```powershell
.\examples\NT26FxDx_OpenKit\tirtc_pro\build_app.bat
.\examples\NT26FxDx_OpenKit\tirtc_pro\build_assets.bat
```

两条命令分别写入上表两个独立的 `gccout` 目录；构建命令的先后顺序不影响烧录要求，烧录仍必须先安装资源、后写正式应用。`build_app.bat` 允许追加 `TIRTC_AUDIO_AEC_EN=n` 等调试参数，不会重新发布合并包。资源源文件位于产品 `resource_store/assets14`；用法见 [资源维护](../resource_store/README.md)。发布复制与校验步骤见 [发布目录说明](../../../../firmware/pro/README.md)。

当前默认 `TIRTC_AUDIO_AEC_EN=y`、`TIRTC_AUDIO_AEC_DELAY=10`，启用利尔达 3A 的 AEC 和 ANS（`bypass=0, mode=1`，与 Lite 一致），AGC 保持旁路。`TIRTC_AUDIO_AEC_EN` 是应用音频后端开关，详细音频调试默认关闭。F6D_D 晚到录音回调保护默认随 AEC 启用，并在停止确认后归还遗漏缓冲；该适配绑定已校验的底包和音频库，升级 SDK 时须重新审核。AI 回复期间持续采集上传，支持边播边听和云端插话打断；AI 网络音频使用 Opus / 16 kHz 单声道，上行 20 ms、目标 24 kbit/s，与 Lite 一致；微信、设备互呼、多人对讲及 LIVE 继续使用原有 G.711 A-law 路径，保留原有音视频业务和音量设置。

Pro AI 工作线程使用与 Lite 相同的 96 KiB 栈，容纳 Opus 固定点编解码的临时数组。为保持应用分区和文件系统布局不变，时钟及六位绑定码使用原 Montserrat 48 的数字子集，保留实际字符的字形、尺寸与字距；重生成和等价校验工具为 `ui/tools/prepare_digits_font.py`。

内存和包大小以 `gccout/tirtc_pro` 的链接报告与当前产物为准。内部文件系统布局为物理 `0x3BC000..0x3E4000`（160 KiB）。
