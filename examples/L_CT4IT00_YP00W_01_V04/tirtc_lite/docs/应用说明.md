# lite · L_CT4IT00 TiRTC application

[产品介绍与演示](../README.md) · [仓库产品选择](../../../../README.md)

This directory contains the product application for the Lierda NT26F6D0
OpenCPU board.  It provides the three-key OLED UI, LTE/network time, device
binding, permanent MQTT, AI chat, WeChat voice calls via the “探鸽小钛” mini program,
device-to-device voice calls, platform LIVE intercom, independent GROUP room
intercom and shared ES8311 audio.

The product code is intentionally separate from Lierda's demonstration tree:

- `src/app`: task composition only;
- `src/core`: one process-wide TiRTC lifecycle, connection owner and verified platform failure adapters;
- `src/services`: LTE, binding and MQTT transports;
- `src/features`: independent AI/WX/DEV/LIVE/GROUP state machines;
- `src/media`: shared audio and codecs;
- `src/ui`: key input, OLED primitives and menu policy;
- `include`: public interfaces between those layers;
- `sdk`: the unmodified, version-locked TiRTC header/archive;
- `board` and `config`: target IO and build-time product policy.

## 默认构建

在 SDK 根目录执行；该入口选择 lite，输出与 pro 分开。修改功能或日志开关后请先清理本产品输出或使用新的绝对 `BUILDDIR`：

```powershell
.\build_tirtc.bat lite
```

编译成功后，统一入口更新 [lite 最新完整烧录包](../../../../firmware/lite/latest.binpkg) 及其 [SHA256SUMS.txt](../../../../firmware/lite/SHA256SUMS.txt)。编译中间产物在 `gccout/tirtc_lite`；下方迁移记录中的命名包独立保留，不会自动覆盖。

`config/tirtc_config.mk` defaults to `DEMO_NAME=tirtc_app`. Build-time log
policy is kept there (currently SDK 3, transport 3, statistics disabled). Restricted-network mode is intentionally fixed in the
runtime adapter for this cellular target; see
[代码与流程详解](代码与流程详解.md).

`HWDEMO_GROUP_ROOM_EN=y` enables the independent room feature by default.
Hold BACK at the ready home screen for about two seconds to enter the assigned
room when AI/WX/DEV are idle; CONFIRM toggles the microphone while reception continues, and BACK exits
the local session. Room assignment stays on the server. The hold threshold is
`TIRTC_GROUP_BACK_HOLD_MS=2000`; use a separate build output directory when
changing feature flags. See [当前设备操作](当前设备操作.md), section 10A.

External JSON parsing now rejects nesting deeper than 16 levels before entering
cJSON. F6D_A task creation also has an application-side failure adapter, guarded
by the supplied OS archive hash. Successful calls and business state machines
keep their existing behavior; supplied SDK archives are unchanged. See
[代码与流程详解](代码与流程详解.md), sections 4.2 and 21.4.

## 当前固件与验证

当前体验入口为 [firmware/lite/latest.binpkg](../../../../firmware/lite/latest.binpkg)，校验值以同目录的 [SHA256SUMS.txt](../../../../firmware/lite/SHA256SUMS.txt) 为准。以下记录保留特定构建的命名包与验证范围；自行编译后不要用历史包的固定哈希校验新的 `latest.binpkg`。

### Lite 上行音频修复，应用版本 02（2026-09-29）

本次更新针对设备互呼和多人对讲中远端听到的失真、杂音及不连续声音，保留全部 Lite 功能。

- 默认麦克风统一为 L7，避免原 L10 在近距离说话时过载；扬声器默认值和各档位表保留。手动调高麦克风仍可能产生削顶。
- 设备互呼改为固定 8 帧队列、独立任务发送，避免同步网络发送阻塞下一次录音；队列载荷独立复制，挂断和重拨校验会话代号。队列满与 SDK 忙的分项计数仅在挂断时输出。
- 仅对互呼和群组上行增加保守的孤立异常采样点处理，不修改原始录音缓冲。这是对已观察到的录音突刺的缓解，不代表已经修复底层 SDK 的全部采集问题。
- 恢复 SDK 日志等级过滤，默认使用 SDK 3、传输 3、关闭详细统计；发布包不含临时录音/发送耗时诊断。
- 硬件录音仍为 16 kHz；互呼、群组、微信仍发送 A-law 8 kHz，AI 仍为 Opus 16 kHz。微信、AI 和 LIVE 未加入异常采样点处理，但共同使用新的默认麦克风档位。

构建与校验：

- AI、微信、设备互呼、远端对讲、GROUP、联网绑定及 UI 功能均按默认配置启用；底包、SDK、收发协议和 Pro 代码未修改。
- 完整包 3,079,880 B；SHA-256：`4bad7793af603ecc67838ee9c2ce6ef2cde5a03add722d266ceed19e7117dab5`。
- 应用 Flash 759,616 B / 812 KiB；静态 RAM 154,228 B。应用 SHA-256：`6746a86939d5936554ddefaac245fd7dc70b5f701e83877d8cf323e00f8f4f4e`。
- 主机回归检查通过：有界队列与突发缓存、SDK 忙、取消/重拨、晚到结果隔离；异常采样点边界、原始数据保留、业务作用范围与日志过滤。
- 02 应用已上板，读回与构建逐字节一致；本次验证只写应用区，绑定和文件系统区域逐字节保留。完整 `.binpkg` 的常规全量烧录方法仍见产品入门页。

实机验证范围：

- 前期验证包已确认互呼、群组、微信和 AI 声音清晰、L7 音量合适；02 去除临时统计并增加互呼突发缓存后，用户反馈“声音清晰，没发现太大的问题”。
- 02 串口记录中，一次互呼正常挂断，发送累计丢弃、本会话队列满及 SDK 忙均为 0；GROUP 发言后正常退出，微信正常结束并可重新拨打。微信累计接收丢弃为 1，不能把本次验证描述为所有业务零丢帧。
- 本轮 02 串口独立覆盖的是 DEV/GROUP/WX；AI 有前期同音频处理代码的实机反馈，LIVE 及其他保留功能完成构建、作用范围和调用流程检查，未取得本轮独立实机日志。以上不是全部网络、音量档位与长期运行场景的保证。
- 发布同步限定为 Lite 音频修复、版本与相关文档及 `firmware/lite` 下载文件；旧历史包、Pro、底层 SDK 和构建工具不在本次更新范围。
