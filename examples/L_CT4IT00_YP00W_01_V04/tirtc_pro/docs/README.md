## 文档、代码、实测各自说明什么

- **功能和默认值**以当前源码为准；UI 的演示输入不代表真实服务器数据。
- **构建与实机验证**以 [release/README.md](../../../../release/tirtc_pro/README.md) 的具体包为准；47 版已编译，但发布记录尚未确认本版实机呼叫。
- **历史资料**如 SDK 同步记录、来源、许可证和生成报告保留原时间与范围，不作为当前性能承诺。
- **UI 配图**为当前源码离线渲染，原生 320×240；不是硬件采集，不证明画质、流畅度或声音效果。
- **演示录像和视频封面**来自用户提供的真实设备视频，保留横竖比例；录像没有固件版本标识，不能代替指定发布包的验收。AI 呼叫片段演示语音，当前代码默认视频策略另按配置篇验证。

以后更新录像时：

1. 保持链接中的稳定文件名，或同时修改首页和正文引用；使用真实录像封面。
2. 检查横竖方向、完整声音和首尾内容，按原比例显示封面，不硬设不匹配的宽高。
3. 更新 manifest 的时长、大小和哈希；如需证明某版已验证，同时记录对应固件版本、测试步骤和结果。
4. 没有录像的功能直接链接操作说明，不设置空视频栏目。AI 呼叫现有录像继续标为语音演示；只有补充对应视频并核对内容后，才修改演示标题。

## 双产品构建与依赖

仓库已经按 **lite / pro** 拆分应用。lite 为 OLED 语音终端，pro 为本触屏摄像头产品；两者共享公共利尔达 SDK 源码、工具链和板级构建入口，业务代码不互相依赖。

| 项目 | lite | pro |
| --- | --- | --- |
| 应用目录 | `examples/L_CT4IT00_YP00W_01_V04/tirtc_lite` | `examples/L_CT4IT00_YP00W_01_V04/tirtc_pro` |
| 对外编译命令 | 根目录 `build_tirtc.bat lite` | 根目录 `build_tirtc.bat pro` |
| 构建选择 | `APP_VARIANT=lite BUILD_MODE=demo DEMO_NAME=tirtc_app` | `APP_VARIANT=pro BUILD_MODE=tirtc` |
| 正常应用输出 | `gccout/tirtc_lite` | `gccout/tirtc_pro` |
| 最新烧录包 | `firmware/lite/latest.binpkg` | `firmware/pro/latest.binpkg`，包含外置 UI 资源的出厂初始化包 |
| 配置入口 | 应用内 `config/tirtc_config.mk` | 应用内 `config` 文件 |
| 底包 | 公共 `components/basePkg/F6D_A`，1.6.0 | 本应用 `board_compat/basePkg/F6D_A`，1.6.04_beta |
| TiRTC | lite 自己的匹配头文件和 `.a` | pro 自己的匹配头文件和 `.a` |
| 演示视频 | 仓库 `assets/videos` 原有素材 | 仓库 `assets/videos/pro` |

pro 默认出厂初始化包包含固件及外置 Flash 字库和背景，一次烧录后直接进入正常应用；**会覆盖外置 Flash 文件**。`build_tirtc_pro_assets.bat` 与 `gccout/tirtc_pro_assets` 作为独立资源安装器的维护入口保留，对应资源数据位于 `release/tirtc_pro/assets14`。只有选择安装器维护模式时，才需要安装后再烧录正常应用。

### 为什么暂时保留两套二进制依赖

两产品已经验证的底包版本不同，TiRTC 虽都为 2.5.0，构建标识也不相同。lite 使用 `v2.5.0-87c3c290`，pro 使用 `v2.5.0-9088239c`，具体以各自来源记录和库哈希为准。将它们强行换成同一个库属于版本升级，可能涉及 ABI、内存布局和接口行为；本次应用目录迁移保留各自匹配依赖，不修改业务策略。

pro 的 [board_compat](../board_compat/README.md) 是必需的构建依赖，不能删除、被公共底包覆盖或通过移除哈希检查绕开。公共 SDK 源码只保留一套，并不意味着所有已验证的私有兼容文件也必须共用。

### 保持功能与构建互不影响

1. 从 [仓库首页](../../../../README.md) 选择产品，再按该产品的 README 操作；不要把 lite 的 GROUP 业务、按键和设置默认值写成 pro 的能力。
2. 产品编译只加载自己的配置、源码和 TiRTC 库；不要跨目录 include、链接对方业务或共用输出目录。
3. 不指定产品时，原 OLED 默认命令继续选择 lite，`BUILD_MODE=tirtc` 继续选择 pro；新开发推荐使用明确的产品脚本。编译原厂 `app/demo` 时不传 `APP_VARIANT`。
4. 正常应用、资源安装程序和原厂 Demo 使用独立输出目录；修改宏后清理对应输出再构建。
5. 分别编译及进行实机回归，记录固件哈希和验证范围。目录迁移与构建成功不等于重新完成全部实机验收。
