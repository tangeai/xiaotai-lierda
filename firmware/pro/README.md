# Pro 固件下载与两次烧录说明

[Pro 产品首页](../../examples/NT26FxDx_OpenKit/tirtc_pro/README.md) · [完整使用说明](../../examples/NT26FxDx_OpenKit/tirtc_pro/docs/当前设备操作.md) · [利尔达官方烧录工具教程](https://opendocs.lierda.com/docs/CAT.1_Doc_Protal/zh_CN/tools/flash/flash-tool.html)

> 当前正式应用包为 `2026_10_21_16_25_22_pro_app.binpkg`，由本轮源码重新编译，包含 AI 退出回调保护、缓冲回收、Lite 麦克风曲线同步及临时调试日志清理；AI 上下行使用 Opus / 16 kHz 单声道。外置 UI 资源未变化，仍配套使用下表的 2026-10-20 资源安装包。该应用包尚未完成本轮实机试听，不以编译和主机检查代替实际效果验收。

使用原版利尔达工具时，当前 Pro 推荐按本文执行：**先烧资源安装包，启动设备并确认 `INSTALL_OK`，再烧正式 Pro 程序包。顺序不能反过来，两次都选择“自定义镜像 → 全量下载”。**

资源安装器不会自动变成正式应用；烧完第一包后，还必须完成第二步。

## 为什么当前采用两次烧录

为节省内部程序空间，当前 Pro 将字库、图片等 UI 资源放在外置 Flash。正式程序和外置资源必须配套，缺少资源会显示 `UI resources unavailable`。

当前已检查的原版下载脚本只选择内部底包和应用，虽然能够解析合并包中的外置资源项，却没有把该项加入实际下载清单。补选外置项后，本板还需要配套的下载模式供电和引脚初始化。因此，包内“包含资源”和工具“已经把资源写到外置 Flash”是两件事，不能仅凭“全量下载成功”判断资源安装完成。

为了让客户继续使用原版工具，目前提供两步安装：第一包启动后由设备程序写入外置资源，第二包恢复正式应用。这样客户无需自行修改烧录脚本。**两次烧录是当前工具流程的兼容方案，硬件本身不要求必须烧两次。** 原厂完善镜像选择和本板初始化、通过完整验证后，可以恢复一个合并包一次下载。

旧版已使用外置字库和背景两项资源，本版扩展到七项；不能把以前能显示 UI 理解为“旧版资源全部在内部”。设备已有匹配资源时，只更新内部程序也能正常使用，但不证明该次下载写入了外置资源。尚未安装资源或只有旧资源的设备，仍应完成本文两步安装。

后续若原厂提供经过验证的单包升级工具，将另行更新配套烧录说明。

## 1. 下载哪两个文件

本次配套文件如下。在仓库文件预览页面使用 **Raw / 下载原始文件** 获取实际 `.binpkg`，不要把网页另存为固件。

| 顺序 | 下载文件 | 大小 | 用途 |
| --- | --- | ---: | --- |
| 第一次 | [2026_10_20_18_15_48_pro_assets.binpkg](2026_10_20_18_15_48_pro_assets.binpkg) | 3,574,232 字节 | 资源安装程序与配套底包；启动后自动向外置 Flash 安装七项 UI 资源。 |
| 第二次 | [2026_10_21_16_25_22_pro_app.binpkg](2026_10_21_16_25_22_pro_app.binpkg) | 3,692,592 字节 | 正式 Pro 程序与完整 F6D_D 底包；不含直接写入外置 Flash 的镜像。 |

两包的时间分别来自各自程序的编译时间，不要求相同。本表两包已核对为配套：底包相同，安装器的七项资源与正式程序要求一致。本轮仅更新正式应用，未修改资源或烧录流程。

目录中的 `2026_10_20_12_18_02_pro_app.binpkg` 和 `2026_10_20_12_18_02_pro.binpkg` 作为历史快照保留，不包含本轮修复；本页当前下载与操作步骤以上表的新应用包为准。

校验值见 [SHA256SUMS.txt](SHA256SUMS.txt)。Windows PowerShell 可执行：

```powershell
Get-FileHash .\2026_10_20_18_15_48_pro_assets.binpkg -Algorithm SHA256
Get-FileHash .\2026_10_21_16_25_22_pro_app.binpkg -Algorithm SHA256
```

逐项与清单对应文件名的哈希比较；大小或哈希不符时重新下载，不继续烧录。

**本流程不要选不带 `_assets` / `_app` 后缀的合并包。** 同目录历史包 `2026_10_20_12_18_02_pro.binpkg` 包含旧版应用和外置 `EFID01` 文件系统镜像，不能替代本轮正式应用；它仅供已验证能正确初始化并写入本板外置 Flash 的工具使用。原版工具某些版本只写内部四项，即使提示全量下载成功，也不能据此确认外置资源已写入。本文两个包不依赖下载模式直接写外置 Flash，也不要求替换工具脚本。

## 2. 两次分别做什么

| 阶段 | 工具写到哪里 | 设备启动后做什么 |
| --- | --- | --- |
| 第一次下载资源安装包 | 内部 Flash：配套底包 + 临时资源安装程序 | 安装程序通过设备自己的 SPI 驱动，把内置资源写入外置 Flash，读回校验，输出 `INSTALL_OK` 后停留等待。 |
| 第二次下载正式程序包 | 内部 Flash：配套底包 + 正式 Pro 程序，覆盖临时安装程序 | 正式程序读取并校验已经装好的外置资源，显示正常 UI，运行业务。 |

两次不是重复烧同一个程序，也不是第一次由下载器直接写外置芯片。**资源安装发生在第一次下载之后、设备正常启动运行安装程序时。**

第二包没有外置文件系统镜像，标准内部下载流程不会替换已经安装好的外置资源。不要额外执行外置 Flash 擦除、格式化，也不要在第二步改用其他版本的合并包。

## 3. 烧录前准备

1. 确认硬件：`NT26F6D0`、`L-CT4IT00-YP00W-01-V04`、配套 `F6D_D` 底包，并有本程序适配的 SPI1 外置 4 MiB Flash。当前存储驱动识别的 JEDEC ID 为 `0x856016`；其他型号需另行适配，不能仅凭容量相同套用。Lite 不使用这套资源安装流程。
2. 下载表中两个包，确认 `_pro_assets` 与 `_pro_app` 不会选错。
3. 按[官方教程](https://opendocs.lierda.com/docs/CAT.1_Doc_Protal/zh_CN/tools/flash/flash-tool.html)安装驱动、打开利尔达烧录工具，使用稳定供电和可传输数据的 USB 线。
4. 提前保存需要保留的绑定信息、设置及文件。**全量下载可能擦除内部用户数据，需要重新绑定和恢复设置；本文不承诺保留原绑定。**
5. 下载前关闭 Xshell、串口助手等对设备端口的占用；查看日志与下载分开进行。端口号以实际枚举为准，不固定为 COM9。
6. 本次使用已编译 `.binpkg`，不需要点击工具的“编译”，也不需要另外选择源码应用文件夹或再次拼接底包。若工具要求硬件型号/连接方式，按官方教程选择与本板匹配的设置。

## 4. 第一次：烧录资源安装包

### 4.1 用工具下载

1. 打开工具的“下载固件”窗口。
2. 勾选“自定义镜像”旁的“启用”。
3. 点击该行“浏览”，选择：

   ```text
   2026_10_20_18_15_48_pro_assets.binpkg
   ```

4. 再次检查完整文件名，确认结尾是 **`_pro_assets.binpkg`**。
5. 点击 **“全量下载”**，按工具提示让设备进入下载模式；不能自动进入时，按该板的官方下载模式操作。
6. 等进度完成、工具明确显示“全量下载成功”。若工具报错，先保留完整下载日志，不进行第二次下载。

### 4.2 让设备运行安装程序

1. 下载完成后让设备退出下载模式、正常启动。若工具没有自动重启，可在下载完成后按 RESET 或重新上电；不要一直按住 BOOT。
2. 打开工具日志功能或串口终端，连接能输出应用日志的端口。若错过启动日志，在采集准备好后重新启动安装程序，再观察完整过程。
3. 安装器启动日志包含：

   ```text
   [assets14] installer starting; matching complete Pro UI resource set
   ```

4. 保持供电，等待安装成功日志：

   ```text
   [assets14] INSTALL_OK files=7 updated=7 skipped=0
   ```

   `updated`、`skipped` 因已有资源而变化，两者合计应为 7。下面这样也表示成功，说明七项资源已经匹配，无需重写：

   ```text
   [assets14] INSTALL_OK files=7 updated=0 skipped=7
   ```

**只有看到 `INSTALL_OK files=7 ...`，才进入第二次烧录。** 工具的“全量下载成功”只说明临时程序下载完成，不代表它已经启动并安装资源。不要用固定等待秒数替代成功日志判断。

安装器没有正常 UI、平台绑定、AI 或通话功能，屏幕没有正常画面属于预期；不能据此判断失败。它完成后会停留等待，不会自动进入 Pro 主界面。看到 `INSTALL_FAILED` 或一直没有成功日志时，先按第 7 节排查。

## 5. 第二次：烧录正式 Pro 程序

1. 确认刚才已看到 `INSTALL_OK files=7 ...`。
2. 关闭日志串口连接，释放设备端口。
3. 回到“下载固件”窗口，保留“自定义镜像 → 启用”，点击“浏览”把文件换成：

   ```text
   2026_10_21_16_25_22_pro_app.binpkg
   ```

4. 检查结尾是 **`_pro_app.binpkg`**，不再是第一次的 `_pro_assets.binpkg`。
5. 点击 **“全量下载”**，按提示进入下载模式并等成功。这里仍是全量下载，不是“应用下载”；两包都带本版配套底包，避免旧底包和新应用混用。
6. 下载完成后让设备正常启动，重新连接应用日志端口，应出现：

   ```text
   [assets14] LOAD_OK font=631201 bg=153600
   [assets24] FONT_CACHE bytes=65536 slots=512 background=153600
   ```

7. 确认进入正常 Pro 界面，中文、背景、绑定码及图标正常。若绑定被清除，按[设备操作说明](../../examples/NT26FxDx_OpenKit/tirtc_pro/docs/当前设备操作.md)重新绑定，再测试业务。

完成第二步后，正常重启不会重新运行临时安装器；正式应用直接使用外置资源。

## 6. 资源与数据保留范围

安装器携带以下完整资源集，共 **876,888 字节**：

| 文件 | 内容 | 字节 |
| --- | --- | ---: |
| `/ui14-font.bin` | 中文及通用字形位图 | 631,201 |
| `/ui13-bg.bin` | RGB565 背景图 | 153,600 |
| `/ui14-meta.bin` | 字体索引与字形尺寸 | 70,108 |
| `/ui48-digits.bin` | 时钟、绑定码的数字字形 | 4,495 |
| `/ui-phone.bin` | 电话图标 | 5,292 |
| `/ui-wechat.bin` | 微信二维码图片资源 | 4,448 |
| `/ui-face-v1.bin` | 表情参数及动画时序 | 7,744 |

安装器先校验内置资源，再检查外置现有文件；仅替换缺失、长度或 CRC 不匹配的文件。写入后同步、关闭并读回校验，最后七项全部通过才报成功。

- 已有可写且有效的文件系统：安装器只处理上述七个路径，不主动删除其他文件。
- 确认整片全空白的外置 Flash：存储驱动会初始化文件系统，不能笼统理解为“任何情况下都不格式化”。
- 未知内容、损坏或只读的文件系统：不会自动清空以强行安装；失败时查看日志并保留需要恢复的数据。
- 工具对**内部**用户区的擦除，与安装器对**外置**资源的处理是两回事。不能据此承诺绑定或设置保留。

## 7. 常见问题

| 现象 | 原因或检查方向 | 处理方法 |
| --- | --- | --- |
| 第一包下载成功，但没有正常界面 | 临时安装器不带业务 UI | 查看应用串口，等 `INSTALL_OK`，然后刷第二包。 |
| 第一包下载成功，却没有安装日志 | 可能未正常启动、仍在下载模式、选错日志口或错过输出 | 确认下载结束，退出下载模式，检查端口占用，再重新启动采集；不能直接认定已安装。 |
| `INSTALL_OK files=7 updated=0 skipped=7` | 已有完整匹配的资源 | 正常成功，可以刷第二包。 |
| `INSTALL_FAILED error=...` | 初始化、空间、读写或校验失败 | 停止后续烧录，保存启动到失败的完整日志；不要直接擦除未知外置数据。 |
| `INSTALL_FAILED error=-28` | 可写空间不足 | 先备份、排查文件占用；安装器不会自动删其他文件腾空间。 |
| `INSTALL_FAILED error=-30` | 需要更新资源，但文件系统受保护/只读 | 检查存储状态及文件系统兼容性，不通过反复刷第二包绕过。 |
| `INSTALL_FAILED error=-74` | 资源长度/CRC 校验不匹配 | 核对包校验值及完整日志，检查存储读写；不要进入第二步。 |
| 第二包后 `UI resources unavailable` / `LOAD_FAILED error=-2` | 正式程序读取资源时有文件不存在 | 确认第一次执行到 `INSTALL_OK`、两包配套、期间未擦外置；按正确顺序重装，仍失败则提供完整日志。 |
| 第二包后 `LOAD_FAILED error=-74` | 程序要求的资源与外置内容不匹配 | 核对配套版本并重新安装资源；继续失败需检查外置读写。 |
| 两包顺序刷反 | 最后运行的是临时安装器 | 等 `INSTALL_OK` 后，再刷一次正式 `_pro_app.binpkg`。 |
| 下载器报 `storage read id fail` | 下载阶段存储访问失败，不能认定已写好 | 确认未误用合并包或额外外置下载选项，检查连接、下载模式并保留日志；点击“编译”不能解决该错误。 |
| 下载后需要重新绑定 | 全量下载可能清除内部绑定数据 | 完成第二步后重新绑定，不从其他设备复制身份凭证。 |

安装途中断电或下载失败，不把半完成安装视为成功。确认供电、连接正常后重新启动或重刷安装器，等 `INSTALL_OK`；若仍报错，先排查，不反复擦除。

## 8. 后续升级还要烧两次吗

- 首次使用、资源丢失或新版资源有变化：使用**同次发布明确配套**的两包，按本文顺序安装。
- 已有资源全部匹配，维护者明确说明该版没有改变资源要求：可以只刷正式 `_pro_app.binpkg`。不能仅凭文件名都有 `pro_release` 判断匹配。
- 已装好资源的设备，即使用忽略外置项的工具刷合并包，也可能正常显示 UI；这只能说明旧资源仍可读，不能证明工具这次写入了外置 Flash。
- 以后原厂工具完整适配本板外置初始化与镜像写入，并验证空白板全量烧录后，可以再采用单包流程；当前本文不要求客户修改工具。

## 9. 开发者重新编译

在完整工程根目录执行：

```powershell
.\examples\NT26FxDx_OpenKit\tirtc_pro\build_assets.bat
.\examples\NT26FxDx_OpenKit\tirtc_pro\build_app.bat
```

两条命令的编译先后不影响产物；**设备烧录顺序仍是安装资源在前、正式程序在后。**

| 编译输出 | 发布用途/后缀 |
| --- | --- |
| `gccout/tirtc_pro_assets/TiRTC_pro_Assets_NT26F6D0_pro_release.binpkg` | 第一次安装资源：`YYYY_MM_DD_HH_MM_SS_pro_assets.binpkg`。 |
| `gccout/tirtc_pro/TiRTC_pro_NT26F6D0_pro_release.binpkg` | 第二次运行正式应用：`YYYY_MM_DD_HH_MM_SS_pro_app.binpkg`。 |

发布时以各自 `.bin` 的实际编译时间（UTC+8）命名，核对底包、分区及资源配套后复制到本目录，更新本页配套表和 `SHA256SUMS.txt`。不要覆盖已有时间戳文件以冒充原来的同一构建。

修改资源源文件后，先按[资源维护说明](../../examples/NT26FxDx_OpenKit/tirtc_pro/resource_store/README.md)重新生成并验证整套资源，再编译两个程序；不能只重编一个并搭配旧资源发布。

现有 `tirtc_pro/build.bat` 仍用于编译正常应用并生成含 `EFID01` 的合并包，**不会自动发布本文两个配套文件或刷新本页配套表**，该流程会重写校验清单。整理两步安装的发布目录后，应重新计算全部待发布 `.binpkg` 的 SHA-256，核对清单与实际文件一一对应。
